# Hyper 请求准备成本、PGO 与 NGINX 对照（2026-10-01）

本轮减少了请求准备阶段的重复分配和监听器复制。实际计数中的分配约由每请求 16.05 次降至 14.05 次，捕获的复制字节减少约 7.4%。完整产品对照和同步 CPU 诊断均未确认稳定吞吐或 CPU 收益，仍未追平 NGINX。PGO 构建流程已跑通，但此次训练没有取得明确收益，未用于保留候选或默认构建。

修改尚未提交、推送或发布。实验性 Hyper 仍需显式启用；默认数据面仍为 Pingora。

## 保留修改

- 每个 worker 共享一个监听器对象，连接和请求持有其 `Arc`。原先每个请求复制监听器配置、socket/shared 引用和 TLS acceptor；配置中的 PROXY protocol 信任列表也随之复制。路由快照仍在每个请求开始时加载，监听器共享不会固定路由或证书版本。
- 普通路由查找借用已经小写的域名，只在含 ASCII 大写时生成小写副本。末尾点、大小写和通配域名的匹配语义保留。这项修改也适用于默认 Pingora 的普通路由。
- 过滤 `Connection` 指定字段时，先识别已知逐跳字段，再解析其余字段名，避免为随后丢弃的 `keep-alive` 等名字分配内存。所有 `Connection` 值仍被处理，其他被指定的字段仍被移除。

连接、请求和后端硬预算、重放策略、超时、流式传输和插件适用条件未放宽。保留理由是删除了可确认的重复工作、代码改动直接、行为验收通过；不是已取得稳定吞吐收益。

## 请求操作计数

OrbStack Linux ARM64，release + jemalloc，单 worker；一个持久连接，10 次预热后 500 次请求，每次验证 200 和完整 1 KiB 响应。分配和复制/时钟分别安装入口探针，未同时运行压测、构建或其他仪器。

| 捕获的指标 / 请求 | 本轮开始版本 | 保留候选 |
|---|---:|---:|
| 分配 / 重分配调用 | 16.048 | 14.052 |
| 累计申请字节 | 2,637.944 B | 2,635.408 B |
| libc 复制调用 | 44.278 | 40.276 |
| libc 复制字节 | 5,919.824 B | 5,484.504 B |
| clock_gettime 调用 | 20.084 | 20.084 |

500 次请求中的 500 次 9 B 和 500 次 10 B 分配消失；候选另外多一次 8 KiB 分配，因此累计申请字节基本持平。计数包含后台操作，不能把累计申请量当作存活内存，也不能将复制下降比例换算为吞吐收益。复制不包含编译器内联实现。

## 完整产品吞吐对照

Rust 1.90，release、thin LTO、单 codegen unit、jemalloc；NGINX 1.28.0。两产品二进制均启用实验性 Hyper，配置完全一致。普通 HTTP/1.1 / 1 KiB 代理，无 TLS、RGL 或访问日志；请求/响应缓冲与上游重放关闭。

一个前端 worker、两个压测线程、两个源站 worker，虚拟 CPU 集合分别为 10 / 2–3 / 6–7。每窗预热 3 秒、测量 12 秒，三轮顺序轮换，每程序每轮两次重复。源站直连窗口约 159,351 req/s；共享环境下这不是持续容量保证。

**36 窗、29,717,275 请求、零错误。** RPS 与 CPU 为窗口中位数，P99 / PSS 为窗口最大值，CPU 为虚拟机进程计时：

观测候选吞吐变化为 +2.75% / -16.41%，CPU 成本变化为 -6.91% / +18.18%；候选约为本矩阵 NGINX 中位数的 89.9% / 72.5%。**这些均不是稳定收益、回退或容量结论。** 原有 A/A 门槛保留：至少三对、零错误、每对 RPS 对称差及两列跨轮 CV 均不超过 10%。所有组失败，最大配对差约 57.18%，最大 CV 约 43.60%。不能只使用低并发数字宣称已逼近 NGINX。

## 同步 CPU 诊断与 PGO

为观察跨窗口漂移，另做三组刻意共享一个前端虚拟 CPU 的诊断：两个相同的旧版进程 + NGINX、旧版 + PGO 试验 + NGINX、旧版 + 保留候选 + NGINX。三个前端同时运行在 CPU 10，客户端各用两个独立 CPU，客户端 CPU 对每轮轮换；共同源站两个 worker。每轮两个重复、并发 64 / 256、同步预热 3 秒和测量 12 秒。每组 36 窗，分别完成 9,939,548 / 9,258,882 / 7,401,139 请求，均零错误。

这是共享调度下的诊断，吞吐不能解释为独立容量。各组绝对吞吐 A/A 均失败；同窗配对可以观察相对偏差，但不能替代既有容量校准：

| 试验 | c64 同窗 CPU 成本变化中位数 | c256 同窗 CPU 成本变化中位数 |
|---|---:|---:|
| 两个相同 ELF | +0.66% | +0.09% |
| PGO 试验 / 旧版 | +0.28% | -0.84% |
| 保留候选 / 旧版 | -0.34% | -0.17% |

相同 ELF 的同窗 CPU 偏差最大为 1.30% / 3.81%，候选变化没有给出明确成本优势。保留候选同窗 CPU 成本约为 NGINX 的 1.44 / 1.50 倍，仅适用于此共享调度实验。不同矩阵的绝对值不能交叉相除。

PGO 使用 LLVM 20.1.8，只对最终 Rust crate 及其中实例化的泛型代码采样，依赖保留普通 release。训练包含原有 101 项集成检查和不同并发的 1 KiB / 16 KiB 代理流量。生成、合并、使用 profile 均成功；PGO 未用于最终候选，也未做其完整发布验收。当前源码已改变，构建工具拒绝继续使用旧 profile。

新[构建工具](../scripts/pgo.py)和[使用文档](pgo.md)保留可重现的可选流程；默认 Cargo、容器和指令集选项未改变。[相同 ELF 诊断](validation/hyper-closegap-shared-control-2026-10-01.json)、[PGO 诊断](validation/hyper-closegap-shared-pgo-2026-10-01.json)、[候选诊断](validation/hyper-closegap-shared-hotpath-2026-10-01.json)及各自的 `-analysis`、`-matched` 文件均保存。

## 尾延迟复测

正式候选的 c64 出现一次 57.685 ms P99，随后按相同配置交错旧版与候选，另做三轮、每程序每轮两次、预热 3 秒和测量 8 秒的独立复测。

**18 窗、14,523,559 请求、零错误。** 旧版 / 候选 / NGINX 吞吐中位数为 92,039 / 93,403 / 118,295 req/s；最大 P99 为 4.493 / 1.959 / 24.880 ms。原尖峰未再次出现，但尚未定位原因，原窗口保留。NGINX 通过此复测的 A/A，旧版和候选未通过（最大配对差约 13.43% / 10.60%）；没有稳定吞吐或延迟改善结论。

## 实际验收与剩余差距

最终非 PGO 候选在 OrbStack 通过双 worker + `listen 0` 生命周期 58 项、综合集成 101 项、产品功能 115 项，以及 Hyper、Pingora 各 49 项 NGINX 行为对照，共 **372 项运行检查**。增加一个重复 `Connection` 字段的真实代理检查，以及大小写、尾点、通配域名三组对照场景。另验证旧 profile 使用及重复生成被构建工具拒绝。

行为对照最初因源站回显的 `Host` / `host` 字段大小写失败；冻结旧版也复现同样失败。修复测试中的字段名比较后，两种内核对照通过。没有为迎合测试而修改线上头部大小写。原始失败、修正后的日志、构建工具拒绝记录全部保存。

格式、Hyper + jemalloc 全目标 Clippy `-D warnings`、默认构建检查与 Python 语法检查通过；它们是静态检查，未计入 372 项。最终 ELF SHA-256 为 `af51b5ed2a1211a925e62966a2c94ae7601c6cb103bdb7f489d1714189f098d3`。三个修改过的 Rust 文件在构建、计数、压测和验收间保持一致。

本轮开始版本的新 CPU 采样中，rgnix / NGINX 自身代码分别占 37.79% / 21.13%，内核占 52.57% / 68.94%。这是独立窗口的平面样本，不是可相加的调用链收益上限。客户端 request future、连接池、HTTP 状态机和生命周期处理仍是主要固定成本。每请求 1,368 B 的客户端 future 分配仍在，调用方移除小分配不足以消除这部分差距。

下一步应在校准可通过的环境中，对连接驱动、连接池归还与客户端 future 做单因素试验。现有连接绑定原型未迁入产品；不能绕过预算、超时、取消和 TLS 等契约来换取比较数字。

本轮没有专用物理机、amd64、非 Linux、TLS/H2/RGL/静态文件吞吐、长时间稳定性或 Kubernetes 多副本容量资格；虚拟机不提供硬件 cycles / instructions。既有 mTLS CA 轮换偶发 reset 未追查解决。
