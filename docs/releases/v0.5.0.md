# rgnix 0.5.0 Preview

HTTP data-plane changes, indexed Gateway routing and reproducible performance diagnostics. This release publishes the current implementation as a preview; it does not claim NGINX performance parity or qualified production capacity.

## Changes

- Keep admitted connection tasks on their assigned worker and bound each worker's blocking pool. Reuse backend selection tables, weighted hash inputs, health-check clients and request metric handles while retaining health and concurrency admission.
- Index Gateway listener, hostname and path candidates, preserve route precedence and reuse the completed request match.
- Reduce unnecessary request-header construction and retain independent RGL request state. Compile new string literals into immutable module constants and release request-only plugin instances after their hook.
- Add a guarded Linux sendfile path for eligible plain HTTP/1 static-file responses. TLS, HTTP/2, compression and transformations retain buffered handling.
- Update the vendored Pingora HTTP/1 path: reuse bounded idle transport groups, avoid redundant session-state copies, use bounded borrowed task queues with Tokio cooperative scheduling, and defer timeout watchdog checks until I/O becomes pending. Single-attempt uploads avoid unused automatic retry buffering; inspected request bytes still forward once.
- Add `--upstream-keepalive-pool-size` and Helm `upstreamKeepalivePoolSize`. The default remains 128 per worker, shared across upstream groups within each listener/protocol pool; raising it may trade file descriptors, memory and tail latency for reuse.
- Publish the NGINX/OpenResty benchmark harness, raw windows, rejected experiments, source-validation records and the subsequent Pingora audit. Newly proposed header-array, body-ownership and vectored-write optimizations are not included.

## Install and verify

Download `rgnix-0.5.0-linux-amd64.tar.gz` or `rgnix-0.5.0-linux-arm64.tar.gz` with `SHA256SUMS`. The archives contain the executable, examples, bilingual README, documentation and ELF dependency metadata. Debian 12 / glibc 2.36 is the build baseline.

```sh
docker pull ghcr.io/samuelsupe/rgnix:0.5.0
helm upgrade --install rgnix oci://ghcr.io/samuelsupe/rgnix/charts/rgnix \
  --version 0.5.0 --namespace rgnix-system --create-namespace \
  --set shutdown.enabled=true --set reportReplicas=true
```

The image supports Linux amd64/arm64; `rgnix-0.5.0.tgz` is the offline Helm chart. Verify archive checksums, GitHub attestations and the image signature using the [release guide](https://github.com/SamuelSupe/rgnix/blob/v0.5.0/docs/releases.md).

## Validation and known limits

Publication requires native amd64/arm64 formatting, Rust/behavior checks, Clippy and release builds, followed by the amd64 Gateway/TLS/gRPC suite on three kind nodes with pinned Gateway API v1.6.1 CRDs. The manual candidate run uses 200 additional routes and 600 seconds of mixed traffic; the tagged run repeats the configured gates with at least 120 seconds. CI separately exercises Linux XDP/kernel/libxdp behavior. Actual run conclusions and artifacts are available in [GitHub Actions](https://github.com/SamuelSupe/rgnix/actions).

The [round-nine source record](https://github.com/SamuelSupe/rgnix/blob/v0.5.0/docs/validation-performance-round9-2026-09-27.md) passed 640 distinct application, vendor and HTTP/product checks. Those historical tests used the identified ARM64 diagnostic artifact, not the later Rust 1.98 release archives; the release workflow does not execute the same complete vendor-test set.

Performance qualification remains open. The two-worker / 64-connection comparison observed 103,596 req/s for rgnix and 194,876 for NGINX 1.30.5 on 1 KiB proxying. Same-binary calibration failed at 64 connections (12.23% paired difference), and a separate 256-connection calibration window had 40.911 ms P99. Do not interpret small changes as stable improvement. The later minimal-proxy diagnostic uses our patched Pingora dependencies, not an upstream vanilla baseline. [Performance guide and raw evidence](https://github.com/SamuelSupe/rgnix/blob/v0.5.0/docs/performance.md).

Full Gateway conformance, long-duration capacity, physical-node/network failures, production CNI and NIC performance, and Redis Sentinel/Cluster failover remain outside this preview's acceptance. Multiple kind nodes share one physical runner.

## Upgrade from v0.4.0

- Back up configuration and durable history; preserve controller checkpoint ConfigMaps. Review rendered manifests and wait for replica configuration convergence before continuing rollout.
- New `.wasm` output may import `rgnix_v1.constant`, which v0.4.0 does not provide. Upgrade servers before publishing newly compiled Wasm, or compile with the oldest server version still in service. Existing literal/memory-based Wasm remains supported. Deploying `.rgl` source lets each server compile its own compatible module.
- The new idle-pool flag requires v0.5.0. Helm leaves its override unset by default. When rolling back to v0.4.0, clear `upstreamKeepalivePoolSize` and use the previous chart/image and compatible plugins.
- Connection worker assignment and blocking-pool limits change scheduling. Revalidate cold-file storage, small numbers of long-lived connections, listener count, CPU and FD budgets in your deployment. Pool-size changes require restart.
- XDP remains opt-in with ABI 2. No new XDP privilege or CRD requirement is introduced by this release. Do not downgrade Gateway CRDs as part of an application rollback.
