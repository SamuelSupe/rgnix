# rgnix 0.3.0 Preview

Programmable HTTP, Kubernetes Ingress and Gateway API in one Rust binary. This preview extends the governance and observability introduced in v0.2.0.

## Changes

- **Gateway API:** pre-provisioned Gateway, HTTPRoute and GRPCRoute support, weighted Service routing, ReferenceGrant, live endpoints and certificates, JWT/external auth, mirrors, staged release controls and BackendTLSPolicy CA/hostname verification.
- **Durable recovery:** accepted Gateway plugin source and route policies persist in controller-namespace ConfigMaps. Restart recovery rechecks live permissions, endpoints and Secrets; resource deletion and same-name recreation cannot revive stale configuration.
- **Shared rates:** optional Redis-coordinated request-rate quotas for routes and namespaces, with bounded queries and explicit closed/open/local dependency-failure behavior. Concurrency and CPU/memory budgets remain per process.
- **Business-metric rollback:** sustained external metric failures can trigger a fallback, with explicit handling of unavailable providers and rollback state preserved across replicas and restarts.
- **Observability:** upstream timing/reuse, body traffic, controller/tenant/budget/process metrics, Helm ServiceMonitor and alert examples; W3C propagation, auth/mirror child spans and correlated local/OTLP logs.
- **Migration:** NGINX assessment and candidate generation, Ingress-to-Gateway conversion, and offline comparison of request samples.

## Install

Download `rgnix-0.3.0-linux-amd64.tar.gz` or `rgnix-0.3.0-linux-arm64.tar.gz`, plus `SHA256SUMS`. The archives include the executable, examples, bilingual README, documentation and ELF dependency information. They target glibc Linux, not macOS or Alpine/musl.

```sh
docker pull ghcr.io/samuelsupe/rgnix:0.3.0
helm upgrade --install rgnix oci://ghcr.io/samuelsupe/rgnix/charts/rgnix \
  --version 0.3.0 --namespace rgnix-system --create-namespace
```

The image supports Linux amd64/arm64. `rgnix-0.3.0.tgz` is also attached for offline Helm installation. Verify archive SHA256 checksums, image signatures and GitHub artifact attestations using the [release guide](https://github.com/SamuelSupe/rgnix/blob/v0.3.0/docs/releases.md).

## Validation and scope

Publication is gated by native amd64/arm64 Rust and behavior checks, Clippy, release builds and a real Kubernetes Gateway/TLS/gRPC harness on amd64. The earlier OrbStack arm64 P1 acceptance passed 73 Gateway, 70 Ingress-policy and 12 shared-rate checks; its exact binaries and scope are recorded in the [P1 report](https://github.com/SamuelSupe/rgnix/blob/v0.3.0/docs/validation-p1-product-2026-09-25.md). [Release workflow and logs](https://github.com/SamuelSupe/rgnix/actions/workflows/release.yml).

Gateway API is a preview using a pre-provisioned data plane; upstream conformance certification is not claimed. Multi-node failure, cloud LoadBalancer behavior, long-duration load, adversarial tenant capacity and Redis Sentinel/Cluster failover remain outside the release acceptance scope. Mirrors use rgnix policy annotations; the standard RequestMirror filter is not supported.

## Upgrade from v0.2.0

- Back up configuration, policy/credential files, certificates, plugins and durable history. Render and review the chart's RBAC before upgrading; Gateway mode requires the pinned standard CRDs and additional resource permissions.
- Helm now defaults to the versioned GHCR image. Keep explicit image/chart versions or digests; no `latest` tag is published.
- Shared rate limits are opt-in. Give replicas the same coordinator and scope only when they should share quotas; select a dependency-failure policy deliberately.
- Preserve checkpoint ConfigMaps. Checkpoint writes are asynchronous, so only persisted updates survive a crash. Live authorization and revocation checks still apply to restored configuration.
- Listener/worker changes require restart. Rollback uses the previous image/chart with its matching configuration; do not downgrade Gateway CRDs as part of an application rollback.
