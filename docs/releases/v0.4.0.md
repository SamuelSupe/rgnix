# rgnix 0.4.0 Preview

Compiled packet policies, safer Gateway publication and bounded connection draining. This release keeps the single-binary HTTP, Ingress and Gateway architecture and adds optional Linux XDP operation.

## Changes

- **RGL XDP:** administrator-owned `on_xdp()` policies compile through Clang to eBPF. XDP ABI 2 supports observation/enforcement scopes, packet and byte token buckets, expiring address sets, rule metrics, sampled OTLP events, automatic atomic replacement, durable rollback, optional persistent links and PCAP replay. An optional Helm DaemonSet runs separately from HTTP services; compatible libxdp deployments can use dedicated dispatcher artifacts.
- **Gateway routing:** standard HTTPRoute RequestMirror with percent/fraction sampling and reference/TLS enforcement; request and backend deadlines cover streaming responses without replaying requests.
- **Change management:** isolated Gateway/HTTPRoute/GRPCRoute preflight and admission, protected rollout state, replica configuration reports and `rgnix wait` digest/minimum-replica gates. Optional topology constraints spread replicas across nodes.
- **Admission lifecycle:** calls are filtered by old/new IngressClass or Gateway ownership before contacting the webhook. Certificate/key updates are validated and loaded without Pod restart; overlapping CA rotation and optional cert-manager CA injection are supported.
- **Tenant and rollout controls:** bounded background compilation, namespace queue/rate limits, cache reuse, and initial readiness after durable plugin restoration. Staged rollouts aggregate matching fresh candidate samples across replicas before advancing.
- **Draining:** configurable shutdown deadlines, readiness withdrawal and HTTP/1.1 close hints. Active asynchronous requests, including gRPC streams, finish within the remaining shutdown budget before the runtime exits.
- **Performance:** pooled Wasm instances with request-state reset, reduced host-call allocation and XDP scope checks before unnecessary packet processing. Published measurements retain their hardware/workload limits.

## Install

Download `rgnix-0.4.0-linux-amd64.tar.gz` or `rgnix-0.4.0-linux-arm64.tar.gz`, plus `SHA256SUMS`. Archives include the executable, bilingual README, examples, documentation and ELF dependency information. Debian 12 / glibc 2.36 is the release build baseline.

```sh
docker pull ghcr.io/samuelsupe/rgnix:0.4.0
helm upgrade --install rgnix oci://ghcr.io/samuelsupe/rgnix/charts/rgnix \
  --version 0.4.0 --namespace rgnix-system --create-namespace \
  --set shutdown.enabled=true --set reportReplicas=true
```

The image supports Linux amd64/arm64. `rgnix-0.4.0.tgz` is also attached for offline Helm installation. Verify checksums, image signatures and GitHub artifact attestations using the [release guide](https://github.com/SamuelSupe/rgnix/blob/v0.4.0/docs/releases.md).

XDP is opt-in. Compile `.rgl` using Clang with a BPF target, then run precompiled `.o` files with the normal image. Attachment requires a supported Linux kernel/interface, bpffs and BPF capabilities. Start in observation mode and use the documented node selector. [XDP deployment and boundaries](https://github.com/SamuelSupe/rgnix/blob/v0.4.0/docs/xdp.md).

## Validation

Publication is gated by native amd64/arm64 Rust/behavior checks, Clippy and Debian release builds, followed by the amd64 Gateway harness on three kind nodes with pinned Gateway API v1.6.1 CRDs. Tag publication includes 200 scale routes and at least 120 seconds of keepalive traffic during plugin publication and Pod replacement. CI also runs the isolated Linux XDP/kernel/libxdp regression. [Workflow runs and artifacts](https://github.com/SamuelSupe/rgnix/actions).

The pre-release OrbStack arm64 source validation passed **14 Rust tests, 327 native behavior checks, 115 Gateway checks, 71 live Ingress checks and 2 additional admission-scope checks**. Its 180-second workload completed **30,363 requests with zero failures**, P99 **45.67 ms**, including plugin updates and Pod replacement. Certificate rotation and a gRPC stream across Pod termination passed. Exact source/binary identities and failure corrections are in the [Gateway report](https://github.com/SamuelSupe/rgnix/blob/v0.4.0/docs/validation-gateway-hardening-2026-09-26.md); these measurements describe that test artifact and workload.

[XDP validation](https://github.com/SamuelSupe/rgnix/blob/v0.4.0/docs/validation-xdp-enhancements-2026-09-26.md) · [Performance measurements](https://github.com/SamuelSupe/rgnix/blob/v0.4.0/docs/validation-performance-2026-09-26.md).

Full upstream Gateway conformance, 24-hour soak, physical-node/network-partition failures, physical-NIC capacity and production CNI interoperability remain separate qualification work. The three kind nodes share a host. Compilation budgets provide process-local scheduling limits, not operating-system CPU/memory hard isolation. Connections beyond the configured shutdown budget can close.

## Upgrade from v0.3.0

- Back up configuration, credentials, certificate/plugin dependencies and persistent history. Preserve controller checkpoint ConfigMaps; live endpoint, Secret and authorization revocation still applies to restored plugins.
- Review rendered RBAC. Controllers now read Pods and Leases in the controller namespace to report publication and staged-rollout samples. Full replica reporting is enabled with `reportReplicas`; staged rollouts activate the needed reporting automatically.
- Set `shutdown.enabled=true` for the new drain flow. Keep it disabled when deliberately overriding the chart to run an older v0.3.0 image, which does not accept the new CLI flags. The termination grace period must exceed preStop, grace and drain budgets combined.
- Admission ownership filtering and hard topology spread require Kubernetes 1.30+. On first admission enablement, start the TLS service with `admission.register=false`, wait for ready replicas, then enable registration. For CA changes, trust old and new CA bundles until every replica serves the new certificate.
- The default namespace compilation allowance is 60 new sources per minute per replica; cached sources do not consume it. Configure `max_compilations_per_minute` in the administrator policy where needed. Queueing retains valid routes and live revocations.
- XDP ABI 2 objects must be recompiled from older artifacts. Explicitly set `xdp.image.tag="0.4.0"` and the intended interface/node selector. Existing CNI/XDP ownership must follow the documented exclusive-link or dispatcher procedure.
- Roll back using the previous image/chart and its matching source configuration. Remove unsupported new Gateway filters/annotations when rolling back to an earlier version; do not downgrade Gateway CRDs as an application rollback step.
