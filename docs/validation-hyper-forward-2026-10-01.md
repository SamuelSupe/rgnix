# Hyper 固定后端计划与指标句柄缓存（2026-10-01）

本轮在实验性 Hyper 数据面中缓存固定后端及指标句柄，减少普通代理请求的查找工作。实际计数确认，每个普通代理请求的已生成指标查找函数调用从 4 次降至 0 次，分配与复制基本持平。完整产品对照没有确认吞吐收益，连接绑定原型也未取得可迁入产品的性能依据。默认数据面仍为 Pingora；修改尚未提交、推送或发布。

## 保留候选

- 发布路由计划时，普通代理计划直接持有已准备的后端和客户端，不再在转发阶段按后端名称查询目标表。请求仍持有自己的快照，后续发布会重新检查精简路径的适用条件。
- 后端首次使用时缓存连接获取、响应头、完成时间和成功/失败计数的指标句柄。普通代理随后直接观察这些句柄，连接获取观察器的缓存也适用于完整请求路径。
- 指标名称、标签和计数时机保留。原有 2048 个标签的全局上限保留，超限后继续走原来的 overflow 记录路径；未放宽连接、请求或后端预算。

每个快照分别拥有缓存，但句柄指向同一个进程注册表。旧响应体结束时继续更新对应的累计指标，不能在发送响应头时提前计入完成数。已有集成验收增加了两个检查：真实部分响应中的完成延期，以及热更新后旧、新请求分别完成一次。测试使用已有源站和重载阶段，没有新增独立测试设施。

## 独立操作计数

OrbStack Linux ARM64，Rust 1.90、jemalloc、双 worker；一个持久连接，10 次预热后 500 次请求，每次验证 200 和完整 1 KiB 响应。所有已生成的 `MetricVec::with_label_values` 实例均安装入口探针；不包含编译器内联的操作。另一个独立窗口发送一个携带 W3C traceparent 的请求，强制完整请求路径并验证探针记录非零操作。

| 指标 / 请求 | 本轮开始版本 | 缓存候选 |
|---|---:|---:|
| 捕获的指标查找调用 | 4.000 | 0.000 |
| 分配/重分配调用 | 16.074 | 16.114 |
| 累计申请字节 | 2,656.120 B | 2,643.080 B |
| 捕获的 libc 复制字节 | 5,919.920 B | 5,919.872 B |
| clock_gettime 调用 | 20.088 | 20.120 |

控制窗口旧版捕获 4 次、候选捕获 3 次指标查找；连接获取观察器已经使用缓存，完整路径的其余查找保留。计数包含后台操作；申请字节不是存活内存，复制不包含内联实现，这些操作数不能换算为吞吐收益。

探针首次按 Rust 原始符号名安装失败，未形成测量窗口。随后根据 ELF `.text` 地址与文件偏移安装成功；失败日志与修正后的探针源码分别保留。

## 完整产品与 NGINX 对照

在同一 OrbStack Linux ARM64 中使用 Rust 1.90 release、thin LTO、单 codegen unit 和 jemalloc，NGINX 1.28.0。两产品二进制均启用实验性 Hyper；上游重放与缓冲关闭，只测试无 TLS/RGL/访问日志的普通 HTTP/1 / 1 KiB 代理。

为了降低并行负载，本次产品对照使用一个前端 worker、两个压测线程和两个源站 worker，虚拟 CPU 集合分别为 10 / 2–3 / 6–7。这与上面的双 worker 原型和上一轮产品矩阵不同，不能跨矩阵相除计算收益。构建、验收和探针完成后才开始比较，测量期间未运行其他构建、验收或仪器任务。

每窗预热 3 秒、测量 12 秒，三轮顺序轮换，每程序每轮两次重复。源站直连约 287,990 req/s。最终 **36 窗、34,367,831 请求、零错误**；RPS 和 CPU 为窗口中位数，P99/PSS 为窗口最大值：

| 并发 | 程序 | req/s | CPU µs/请求 | 最大 P99 ms | 峰值 PSS MiB | 完整 A/A |
|---:|---|---:|---:|---:|---:|---|
| 64 | 本轮开始版本 | 82,640 | 12.07 | 16.350 | 28.69 | 未通过 |
| 64 | 缓存候选 | 81,012 | 12.31 | 34.267 | 29.12 | 未通过 |
| 64 | NGINX | 103,174 | 9.51 | 6.970 | 12.52 | 未通过 |
| 256 | 本轮开始版本 | 62,484 | 16.01 | 10.809 | 47.75 | 未通过 |

候选观测吞吐变化为 -1.97% / -0.13%，CPU 成本变化为 +1.97% / +1.66%。全部组都未通过既有 A/A 门槛：至少三对、零错误、每对 RPS 对称差与两列跨轮 CV 均不超过 10%。候选最大配对差约 17.08% / 29.31%，两列 CV 最大约 27.47% / 27.54%。不能把这些变化认定为稳定提升或回退，也没有延迟改善结论。

本轮保留缓存是因为它明确消除了重复查找与转发目标查询，且请求和指标契约通过运行验收；不是因为已经测到吞吐收益。观测候选吞吐约为 NGINX 的 78.5%，这不是稳定比例，不能与上一轮 65%–69% 相比来声称缩小差距。降低并行负载没有消除共享环境的波动，专用环境比较仍未完成。

## 连接绑定原型对照

使用此前修复后的同一个独立原型 ELF，以包装器分别启用 legacy/local-workers 和 owned-http1/local-workers。双 worker、四个客户端线程、四个源站 worker，前端 / 客户端 / 源站虚拟 CPU 集合为 10–11 / 2–5 / 6–9。每窗预热 3 秒、测量 12 秒，三轮顺序轮换，每程序每轮两次重复窗口。

36 窗、47,378,650 请求、零错误。RPS 与 CPU 为窗口中位数，P99 为窗口最大值：

## 实际验证与边界

缓存候选在 OrbStack 上通过双 worker + `listen 0` 生命周期 57 项、综合集成 101 项和产品功能 115 项，共 **273 项运行检查**。涵盖流式请求和响应、取消、禁用重放、WebSocket、HTTP/2、重载、TLS/mTLS、认证、RGL 和遥测。

格式、Hyper + jemalloc 全目标 Clippy `-D warnings`、默认构建检查通过。这些是静态检查，未计入运行验收。相关 Rust 源码从构建前到计数和验收完成保持一致；候选 ELF SHA-256 为 `e42e8c3ffb3ab7e4c00378014b011ee5b74c6ec42415fb8ee36efd9d8e90a972`。

本轮没有验证 amd64、非 Linux、专用物理机、TLS/H2/RGL/静态文件吞吐、长时间稳定性或 Kubernetes 多副本容量。既有 mTLS CA 轮换偶发 reset 仍未解释，当前验收通过不能说明它已修复。PGO 和 worker 内指标聚合未实施；先完成可归因的普通代理比较，再决定更复杂的候选。
