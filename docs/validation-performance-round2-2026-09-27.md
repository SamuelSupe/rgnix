# 第二轮数据面性能优化 — 2026-09-27

后续优化、再次分配计数及 A/A 控制见[第三轮报告](validation-performance-round3-2026-09-27.md)；本页保留第二轮原始结果。

**本轮确认减少了每请求分配，但没有证明全场景吞吐提升。** 普通代理、静态文件、只有请求钩子的 RGL 请求头路由，分配调用分别减少约 **6.3% / 11.5% / 9.1%**。保留三处应用层改动，撤回了出现明显回退的 reactor 迁移试验。所有改动仍未发布。

完整三轮中，64 并发 1 KiB 代理的吞吐中位数观察到 **+23.1%**；256 并发同场景则为 **−15.1%**，并出现 **60.590 ms** 的单窗口 P99。其他场景也有吞吐或尾延迟回退。不能挑出最快场景宣称整个产品提速，也不能把异常直接归因于虚拟机。

主矩阵 **84 个窗口、40,877,066 次请求**，另有 12 个短连接窗口、2,608,100 次请求；状态、连接、读、写及超时错误计数全部为零。最终二进制通过 **392 项 Rust/原生行为检查**。正确性通过不等于性能发布门槛通过。

## 保留的改动

- 响应压缩：先判断模块状态、配置和协商结果；只有实际可能压缩时才克隆请求头。MIME 比较借用原始字符串，仍保留 no-transform、Range、SSE、gRPC 和质量权重规则。
- 路径处理：已经规范化的路径直接返回，避免组件向量和重复拼接。百分号、UTF-8、根目录逃逸、重复斜杠及点路径的校验仍执行。
- RGL：通过不可变 `Arc<RequestData>` 将输入交给宿主。只有请求钩子的实例释放后，取回原始数据；有响应钩子时保留其输入视图。异常也恢复请求元数据供日志使用。每请求独立 Wasm Store/实例、fuel、8 MiB 内存和 1 MiB 宿主数据上限不变。

同一二进制也出现约 **47%** 的相邻窗口差异，以及 **31.323 ms** 的普通代理 P99。A/A 无 HTTP/连接错误。它证明当前测量存在很大的环境或运行时波动，不能把 A/B 的百分比直接解释为代码导致的收益或回退；它不能进一步证明具体是宿主争用、虚拟化、连接调度还是其他原因。

**性能发布门槛尚未通过。** 本轮可靠结论限定为分配调用减少和功能回归通过；吞吐表属于诊断记录。需要在噪声受控的环境中重新做 A/A、A/B 和长时尾延迟验证，才适合更新产品整体性能承诺。

## 撤回的试验

曾将接受的 TCP/Unix socket 在握手前重新注册到目标 worker 的 reactor。该版本通过功能回归，独立 reactor 迁移检查也通过，但性能验证未通过保留门槛。先有 [32 个探索窗口](validation/performance-round2-reactor-screening-2026-09-27.json)，随后组合候选的矩阵在 [30 个完整窗口](validation/performance-round2-reactor-rejected-2026-09-27.json)后中止：POST、TLS 和高并发静态文件出现明显回退。已完成窗口全部保留。

这些数据不能单独证明 reactor 迁移就是根因；当前噪声下同样不能证明它安全改善了性能。因此本轮撤回该改动，保留上一轮的运行时、阻塞池和连接调度。实验的独立单元测试与 100 次启停结果不计入最终保留版的 392 项检查。

## 环境与复现

- OrbStack 2.2.3 / Ubuntu 25.10 / aarch64，原生 `/tmp` tmpfs；Rust 1.90.0，release thin LTO、单 codegen unit，同一 Cargo.lock。宿主与其他 VM/任务共享，CPU 绑定不等于独占物理核心。
- 服务端两个 worker 固定在 VM CPU 10,11；wrk 四线程在 2–5；统一 OpenResty 1.31.1.1 上游四 worker 在 6–9。主矩阵压测端最高 1.29/4 核、上游最高 0.99/4 核。
- 主矩阵每窗预热 1 秒、测量 6 秒，64/256 并发、三轮。`--interleave` 每个场景/并发分别启动两个版本、紧邻测量，逐轮轮换先后及场景顺序。每次启动都做完整功能预检，包括 POST 完整正文长度/MD5、分流后端、头部、TLS 和静态正文。
- 关闭访问日志、OTLP、压缩、配置的认证/限流与自动上游重试；正常指标、进程/插件预算和 Wasm 沙箱保持工作。构建、回归与 Heaptrack 不与正式窗口并行。
- 此处每个窗口都是新进程，PSS 不应直接与上一轮混合负载进程的高水位比较。没有使用内容缓存、改写响应内容或删除错误窗口来提高数字。

```bash
python3 scripts/benchmark_compare.py \
  --rgnix /path/to/previous-optimized-rgnix \
  --candidate /path/to/current-rgnix \
  --nginx /path/to/nginx --openresty /path/to/openresty \
  --engines rgnix candidate --interleave \
  --work-dir /tmp/rgnix-new-run --output /tmp/rgnix-new-run.json \

```
