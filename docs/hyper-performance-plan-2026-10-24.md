# Hyper 请求路径性能提升方案（2026-10-24）

基线 main `3a44af7`，受测 release ELF 与上轮候选相同。目标是减少可验证的用户态工作及跨任务开销，保留产品、协议和资源上限契约。每个阶段独立验证后再组合；无通过重复性门槛的结果不作为吞吐承诺。

## 证据校正

- 正式压测的 CPU 中位数与独立 perf 窗口比例不能相乘构成同窗内核/用户态微秒预算。现有数据只能支持用户态工作明显更多的方向。
- HTTP/1 客户端池已按 worker 分开，池 mutex 不直接证明跨 worker 争用；全局指标、快照与预算仍可能有共享写入。
- 当前 OrbStack 对 cycles/instructions 报不支持，perf c2c 报无内存事件 PMU。保留失败输出，提供同负载的 1/2 worker 原生 PMU 复现入口；不伪造 IPC/HITM 结论。
- epoll 次数不能唯一反推出任务 poll 次数；Date 已按线程缓存格式化结果；仅在需要自动添加 Date 时检查时钟，已有上游 Date 透传不触发该生成路径。

## 实施阶段

1. 测量基线：固定二进制、编译器、配置、CPU 亲和性，记录 PMU 能力、1/2 worker、1/16 KiB、64/256 并发；仪器与正式容量窗口分开。
2. 首部、Host 与路由：标准 HeaderName 常量；只删除实际存在的 hop-by-hop 字段；普通合法 Host 借用并在需要时转小写，复杂 authority 保留原解析器；路径查找使用配置中实际存在的前缀长度；无请求体时延迟共享计数。保护 Host 重复/无效、Connection 指定字段、Unicode 和 Ingress 路径边界。
3. 时间和预算：首先消除重复时钟检查，不把精确截止时间或请求时长替换为毫秒粗时钟。将只做 try-acquire 的全局请求预算改为非等待原子预算，保留整个进程的强上限、取消释放和 draining 语义；不按 worker 平分固定额度。
4. 指标：保持现有指标名称、标签、全局/路由/复用延迟分布和 scrape 可见性。评估独立 shard 的 collector 汇总，不能以删 histogram、异步丢失观察或额外无界标签冒充优化。
5. 普通 H1 上游：复用 Hyper 的现有 HTTP/1 编解码器，试验由请求/响应 body 持有并驱动 Connection，消除额外连接任务。worker 本地池有硬全局闲置预算；checkout 检查 EOF/到期，半消费 body、取消、异常与不确定连接不可归还；禁止重放。HTTP/2、HTTP/3、升级和策略路径保留原实现。先以真实 socket 验证后衡量 1/16 KiB 及任务/分配计数，再决定是否默认采用。
6. 验收：按阶段保留 patch、指令 A/A、分配/复制/时钟计数、运行回归、正式吞吐/P99、失败与回退。1% 指令门槛；正式吞吐 A/A/CV 10%、P99 20%，全部窗口保留。独占物理核上的 PMU、c2c 和稳定容量作为环境资格项单独列出。

## 不变量

保留进程级并发和闲置连接总预算；保持热更新快照生命周期和 passive health/least-connections 诊断；精确超时不能提前或因慢速字节续期；指标不删字段、不丢观察；取消不复用半开连接、不重放已发送请求；流式 body 保持背压，不能为复用而无界缓存。
