## 采用的两处改动

1. **连接 URI 只在池未命中时构造。** 原普通转发每次构造包含 scheme/authority 的 URI，内联客户端随后又构造 origin-form。现在普通 origin-form 保留原路径和查询串；绝对 URI 只做必要的一次 origin-form 转换。SocketAddr 和 TLS 连接 URI 在新建连接时生成，复用时省掉 authority 查表、URI 往返构造和对应引用计数。配置 Host、实际 TCP 目标和 TLS 校验名称仍各自按原契约处理。实现提交 `3e611ef`。
2. **无百分号的路径直接借用。** 仍先检查 8 KiB 长度，再对含 `%` 路径严格验证转义及 UTF-8、解码；无 `%` 路径跳过逐字节转义检查和百分号解码。后续前导斜线、控制字符、反斜线、重复斜线、点段和路径归一化规则保持。路径精简来自 `c826976`，最终提交 `57b069e` 撤回了其中的 h2c 试验。

没有引入新依赖、定制 HTTP codec、粗时钟或新的缓存配置；全局强预算、指标、响应体背压、取消与不重放规则不变。此前单 worker 超出闲置容量时的连接周转代价仍存在，本轮没有修改池的容量或归还策略。

另试验了仅在收到 h2c Upgrade 时才克隆关闭监听器。虽然减少共享引用操作，直接配对中它使指令比 URI 单项增加约 0.66%；flat self 的 `__GI_memcpy` 增加约 552 指令，独立探针的 libc 复制从 5,479 增至 9,879 B/请求，主要新增归于 server dispatch 的 recv_msg。最终撤回这一试验，保留原 h2c 处理并重新完成整组验证。未将源码操作数减少当作性能收益。
